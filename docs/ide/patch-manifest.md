# IDE patch manifest

One coherent change per patch, applied in order by `ide/build.sh`. The
stack must apply cleanly to the pinned upstream tag; `build.sh` fails
closed when a patch does not.

Upstream is pinned by `ide/upstream-version.txt` and checked out to the
gitignored `ide/upstream/` by `ide/build.sh` with
`git clone -c core.autocrlf=false --depth 1 --branch <tag> https://github.com/microsoft/vscode.git upstream`.
Git for Windows still checks out CRLF (system-level `* text=auto`), so
`build.sh` sets `core.whitespace=cr-at-eol` before applying the LF patches.
Patch 0002 is generated by `ide/scripts/rebrand.py --upstream ide/upstream`
and captured with `git -C ide/upstream diff`. The stack is checked with
`ide/tests/patch-smoke.sh ide/upstream`, which must pass before a build.

## Rebase status

**The stack is rebased onto `1.137.0`, applies cleanly end to end, and
produces a working tarball.** `ide/tests/patch-smoke.sh` reports 43 passed,
0 failed on a patched tree, and `sh ide/build.sh` exits 0 with
`ide/out/jahaziel-code-server-<slug>.tar.zst` plus its `.sha256` sidecar.

Notes on the rebase (2026-09-25):

- 0001 was re-merged by key, keeping 1.137.0's extra keys (`sharedDataFolderName`, the
  darwin profile UUIDs).
- 0002 was regenerated with `ide/scripts/rebrand.py` rather than hand-merged; the old
  capture no longer applied.
- 0003 keeps the 1.137.0 selectors (`.monaco-workbench.*`, `.issue-reporter-body`) and
  applies only the font change.
- 0005 is now intentionally hunk-less: upstream 1.137.0 already removed the AI surfaces it
  used to delete, so there is nothing left to remove.
- 0007 and 0009 are captured with `git diff --binary`; without it the icon and image
  deletions cannot be replayed.
- 0009 removes the GitHub auth records as whole statements, not line deletions, so brace
  structure stays valid.
- Binary and hunk-less patch handling in `ide/build.sh` were both fixed; the allow-list
  comparison never matched a multi-entry list.
- 0009 no longer touches `workbench.html`: its tablet style and script blocks
  duplicated 0014's (including a baked-in `>>>>>>> theirs` marker from a bad
  capture), and its branding-link line belonged to 0013, which runs later. 0009
  keeps the auth-record and callback-registration changes; its `create()` now
  registers the URL callback unconditionally instead of dropping registration
  with the removed github-authentication carve-out.
- 0013 adds the two stylesheet links its own hunk needs, so it applies to the
  pristine file; 0014 owns the tablet style and script on top of it.
- 0017 deletes the two auth extensions. Deletion patches must be captured
  against the fully patched tree (commit it first, then diff): capturing after
  `rm` records pristine pre-images, which no longer match once 0002 has
  rebranded the same files.
- `git apply --3way` resurrects `rm`-deleted files when their blobs exist, so
  `build.sh` passes `--exclude` for the stripped extensions.
- `install-deps.mjs` only skips a directory whose
  `node_modules/.package-lock.json` marker exists; a bare `node_modules`
  directory may be a leftover partial install.

Security-relevant patches (0004 telemetry, 0007 remote extensions, 0010 autoupdate) were
rebased with the same intent, not re-scoped. Two-approval review still applies to future
rebases.

### Upstream bugs worked around at this tag

- The gulp `mangler` task aborts with "Protected fields have been made PUBLIC"
  on 1.137.0, so patch 0015 builds the `*-min` target with upstream's own
  `compileBuildWithoutManglingTask` instead.
- Two regexes carry literal non-ASCII characters that survive esbuild
  minification and trip the build's non-ASCII output check, so patch 0018
  spells them as escapes (identical semantics): the em dash in
  `chatGoalSummaryService.ts` and the chevron class in `outputMonitor.ts`.
  Both are pristine-upstream bugs, not rebase regressions.
